Prototype notes & keyboard differences

This is an HTML UI study, not the Zellij plugin. All five tools are initially marked installed by fixture data, not PATH discovery. Refresh simulates discovery. Paths, relative times, executable labels and ten initial events are fabricated demo fixtures under /home/demo. History is in memory only and resets on reload; duplicates are retained.

Path suggestions use a small, static, directory-only fixture list with simple prefix filtering; no fuzzy scoring or real filesystem enumeration runs here. The real single-WASM design selects embedded Frizbee (neo_frizbee), with no external companion binary. Frizbee is not implemented in this page.

Tab / Shift+Tab move forward / backward through path, tools and history. ↑ / ↓ highlight suggestions; Enter accepts a highlighted suggestion without launching. Press Enter again to launch. With no suggestions, ↓ focuses tools. Tools use ← / → to select, ↑ for path, ↓ for history. History uses ↑ / ↓ to select and Enter to relaunch. Clicking a tool or history row only selects it; explicit launch buttons submit. Escape dismisses transient UI first; otherwise an untouched dashboard is replaced by a closed-pane placeholder.

Ctrl+P / Ctrl+T / Ctrl+R are handled only when the browser delivers them. Some browser or OS shortcuts cannot be intercepted (notably Ctrl+T). Mouse controls are the reliable alternative. Tab is owned by the three command areas to switch sections. Browser focus outlines, scrolling, proportional pixel breakpoints and CSS ellipsis approximate terminal behaviour; they are not terminal-cell or Zellij normal/locked-mode verification.
